# v0.20261010.0 実装計画・報告

## 設計

- Windows 11向け C# / .NET 10 / WinForms。外部NuGet依存なし。製品名 TraySnip。
- フェーズ1: 独立Git、文書、ビルド環境とプロジェクト、計算・保存・キー判定を検証可能な構成。
- フェーズ2: 撮影・ショートカット・トレイ・設定を統合し、ビルド・自動テスト・対象限定UI確認を実施。
- PerMonitorV2で起動し、モニタごとのオーバーレイと共有する物理ピクセル座標で選択する。負座標、混在DPI、モニタを跨ぐドラッグを扱う。
- 4種類の静止画撮影。Win+Shift+Sで既定モードを起動。Escape/右クリックでキャンセル。撮影中の再入を抑止。
- WH_KEYBOARD_LLを専用メッセージループで処理し、対象キーのdown/repeat/upだけを抑止。コールバックで撮影・保存しない。一時停止時は入力を透過し、終了時にフックを解除。
- 標準Snipping ToolやOSのポリシーを変更しない。終了中はWindows既定のショートカットに戻る。
- クリップボード（STA、競合時リトライ）とPNG保存を独立して試行し、一方の失敗で他方を失わない。
- 既定保存先はピクチャ/TraySnip。日時を含む名前で上書きを避けて保存。保存画像を自動削除しない。
- 個人設定は実行ファイルの隣のdata/settings.json。設定画面で保存先・既定モード・ショートカット有効状態を変更可能。
- トレイ右クリックに各撮影モード・設定・保存先を開く・一時停止・終了。左ダブルクリックで設定画面。二重起動を防止。
- ユーザー向けの自動起動登録は任意のPowerShellスクリプトとし、初期状態でWindowsの起動設定を変更しない。
- デプロイ先はartifacts/app。SDK・実行物・撮影画像・個人設定はGit対象外。

## 調査（2026-10-10）

- [Microsoft Support: Snipping Tool](https://support.microsoft.com/en-us/windows/apps/use-snipping-tool-to-capture-screenshots): 矩形/ウィンドウ/全画面/自由形状、Win+Shift+S、自動保存、クリップボードを用いたコピー。編集/録画/OCR等もあるが今回の要求範囲外。
- [RegisterHotKey](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey): Windowsキーの組み合わせはOS予約。既存キーの再登録を主要方式にしない。
- [LowLevelKeyboardProc](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelkeyboardproc): 非0で抑止可能。専用スレッド・メッセージループと速やかな復帰が必要。タイムアウト時は通知なくフックが解除され得る。
- [High DPI](https://learn.microsoft.com/en-us/windows/win32/hidpi/high-dpi-desktop-application-development-on-windows) / [Virtual screen](https://learn.microsoft.com/en-us/windows/win32/gdi/the-virtual-screen): 物理ピクセルと負の仮想スクリーン座標を扱う。
- 置換は公式の既定アプリ登録ではなく実行中の入力抑止。OS更新、他アプリのフック、セキュアデスクトップ、リモート環境では実機確認が必要。

## 検証方針

- Releaseビルド、警告ゼロ、git diff --check。
- 負座標・逆方向選択・画面境界・自由形状のマスク・PNGの同名回避・設定破損・キーのrepeat/upと余分な修飾キーを自動検証。
- 設定画面の主要コントロール寸法と、配線を壊すと検出することを確認。
- UI検証はテストウィンドウの範囲に限定。実際の複数ディスプレイ構成や物理ショートカットの未検証項目は明記。

## 実施結果

- フェーズ1: .NET SDK 10.0.401を公式配布ZIPから取得しSHA512照合後に.toolsへ展開。Releaseビルドは警告0・エラー0、基盤テスト1件成功。外部NuGetパッケージなし。
- NuGet設定の読み取りはサンドボックス外で必要だった。ユーザー設定の変更は行っていない。
- フェーズ1コミット: `6343eb1`。
- フェーズ2: 撮影、トレイ、設定、キー捕捉、PNG保存、クリップボード転記、起動スクリプトを実装。
- 保存用bitmapはworkerへ所有権を渡してクリップボード用と分離。保存応答が10秒を超えた場合はUIを解放し、保存処理が継続中であることを表示する。
- 設定保存失敗時は変更前の一時停止状態を復元する。セッションのunlock/connect後はキー解放イベント欠落に備えてフックを再作成する。
- 設定UIの不要な縦余白を削減。外部ダイアログは使用しない。アプリ内のUI例外も独自の設定画面で通知。
- published apphostはプロジェクト内SDKのランタイムとシステムランタイムを探索する。[公式MSBuild設定](https://learn.microsoft.com/en-us/dotnet/core/project-sdk/msbuild-props#apphostdotnetsearch)に基づく。
- 実撮影の `CopyFromScreen` に複合ROP値を渡す案を見直し、許可された `SourceCopy` 単独へ修正。[.NET公式実装](https://github.com/dotnet/winforms/blob/v10.0.0/src/System.Drawing.Common/src/System/Drawing/Graphics.cs)では複合値を例外にするため。回帰検査を追加。
- SDK初回実行の一部にASP.NET開発証明書のインストール表示があった。証明書の信頼登録は実施していない。以降は共通スクリプトで生成を無効化している。

## 検証境界・運用

- 実行環境が認識する画面は1920×1080の1台。負座標/境界は計算・画像テスト、複数overlayは1画面を2領域に分けた実入力テスト。実物理マルチディスプレイ・混在DPIを合格扱いにしない。
- 自動UI試験では利用者のデスクトップ全体を撮影していない。選択テストは合成bitmap、目視用画像は設定ウィンドウ内だけ。
- 利用者のクリップボードは試験で変更していない。実画像撮影から他アプリ貼り付けまでの一連の確認、ウィンドウ/全画面の実撮影、ネットワーク遅延、lock復帰、HDR、RDPは未実施。
- Windows起動時の自動起動は登録していない。必要ならREADMEのstartup.ps1を使用する。
- Windows予約ショートカットの公式差し替え登録ではなく、常駐中の入力捕捉。OS更新や他のフックとの競合時は再確認する。
