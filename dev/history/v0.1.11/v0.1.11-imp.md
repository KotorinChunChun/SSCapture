## 2. ショートカットキーと入出力プリセットの組み合わせ（12・14・15）

「設定 → ショートカット」に「プリセット撮影」の一覧を置く。静止画専用で、録画は既存の録画キーから開始する。1行の3欄を左から選び、「追加」「削除」で行を管理する。次は登録例で、新規設定でキーを自動割り当てすることはない。

| ショートカットキー | 入力プリセット | 出力プリセット |
| --- | --- | --- |
| Ctrl＋Alt＋F6 | 固定サイズ 1280×720 | ファイル保存 |
| Ctrl＋Alt＋F7 | 固定サイズ 1280×720 | クリップボード |
| Ctrl＋Alt＋F8 | 既定を使う | クリップボード＋ファイル |

- キーを押したときにその行の2つのプリセットを解決する。入力・出力はそれぞれ「既定を使う」も選べる。固定サイズなら枠を置き、固定位置とサイズなら登録位置で撮る。明示した出力のコピー・保存・編集・ピン留め等は、その撮影に適用する。
- 同じ入力または出力を複数行で共有できる。プリセットは既存のIDで参照し、名前を変えたら一覧にも反映する。参照中のプリセットを削除するときは該当行を示し、別のプリセットへ変更するか、その割り当てを削除して確定する。
- 入力・出力プリセット画面のキー欄は、該当する組み合わせをこの一覧で開く入口にする。キーの保存先はこの一覧に一本化する。設定の「保存」で有効な行を一括適用する。行の不備、通常撮影・録画・即時撮影・再撮影キーとの重複、登録失敗時は、該当するキーと行を表示し、それまでの割り当てを利用できるようにする。
- v0.1.10から初めて読むとき、割り当て済みの `SavedRegion.Shortcut` を「元のキー／元の入力ID／既定の出力」の1行に移す。旧キーと移行行が二重に発火しないよう、以後は一覧を登録元にする。一覧の項目が設定ファイルに存在するかで移行済みと判定する。保存済みの空一覧から削除したキーが復活することを防ぐ。各行に正規化したキー、入力ID、出力IDを保存し、「既定を使う」は実行時に解決する参照として表す。旧固定位置キーは従来の即時出力（コピー・ファイル、外部起動とフォルダー表示なし）を移行行に記録し、利用者がその行の出力を明示指定したときに通常の出力へ切り替える。
- 行を実行してもプリセット本体・★既定は書き換えない。撮影中の右クリックによる入力／出力の切り替えは選んだ側だけに適用する。通常撮影・録画・再撮影とモニター別の即時撮影は、既存の専用欄で設定する。

入力・出力プリセットのボタンは「★既定にする」とし、ポインタを画像に含める設定名は「マウスカーソル」に統一する。既存の設定名 `IncludeCursor` を読み書きする。

`--capture-preset` はGUIの一覧と同じ解決処理へ入力・出力IDを渡す。既存の `--capture-select` は対話選択、`--capture-region` は明示座標の撮影に使う。[入力プリセット画面](../../../src/SSCapture/UI/RegionManagerForm.cs)・[出力プリセット画面](../../../src/SSCapture/UI/CapturePresetEditor.cs)・[キーの入口](../../../src/SSCapture/TrayApplicationContext.Input.cs)・[CLIの入出力プリセット解決](../../../src/SSCapture/Services/CaptureCommandLine.cs)

## 3. 日本語のキー表示と操作ヒント（02・09）

保存するキーと利用者に見せる文字を分ける。たとえば保存値 `Win+Shift+S` は「Windows キー＋Shift＋S」、`Left` は「←（左）」、`NumPad1` は「テンキー 1」と表示する。Ctrl・Shift・Altはキートップで探せる表記を使う。日本語配列の記号・変換キーは実際の配列に対応する表示を使う。表示文字を再解析してキーを保存する処理は設けない。

- 設定のキー選択、プリセット撮影の組み合わせ一覧、トレイ、通知の再撮影キー、両方の操作ガイドで表示関数を共有する。通知は未割り当て時にキー案内の行を省く。
- 画面右下のガイドは現在のモード、操作段階、実際の割り当てから作る。既定の矩形ドラッグなら「Shift　縦横比を固定」「Ctrl　起点を中心にする」「Ctrl＋Shift　両方を適用」「Windows キー　押しながら別のモニターへ移動」を掲載する。待機中のWindowsキーは短押しのウィンドウ撮影切り替えと、長押し移動を区別する。AltやWindows キー＋Altも割り当てに従う。
- ポインタ横には今効いている操作とその時点で使える取消方法を表示する。変更済み・未割り当てのキー、右クリック取消の無効化も反映する。画面右下とポインタ横の表示設定は独立させる。

変更の中心は [HotkeyEditor](../../../src/SSCapture/UI/HotkeyEditor.cs)、[CaptureKeyMap](../../../src/SSCapture/Capture/CaptureKeyMap.cs)、[右下のガイド](../../../src/SSCapture/UI/SelectionGuideForm.cs)、[撮影セッション](../../../src/SSCapture/Capture/CaptureSession.cs)。日本語表示を追加した後も既存のJSON、CLI、ヘルプで使う識別子を読めることを確かめる。

## 4. 精密選択と2点クリック（05・06）

**拡大鏡と矢印**　基本設定の「操作ガイド」に拡大鏡のスイッチを置く。既定はOFFとし、矢印による微調整は拡大鏡の表示にかかわらず使える。ポインタ下のプレビュー元画像から小範囲を整数倍・最近傍で拡大し、中央の1画素を示す。画面端では表示位置を反転する。複数モニターの仮想画面をキー入力やマウス移動のたびに再取得しない。

撮影選択画面に入力がある間、矢印1回で実際のポインタを物理1px動かし、通常のポインタ移動と同じ経路でヒット判定・枠・拡大鏡を更新する。OSから返る同じマウス移動を二重適用しない。微調整した座標にグリッド・枠スナップをもう一度掛けて動きを失うことを防ぐ。方向ロック・比例制約は表示中の選択に適用する。固定サイズのShift＋矢印は従来の10px移動を維持する。モニター制限の解除キー、負の座標、異なるDPIを同じ物理座標で扱う。

**2点クリック**　入力プリセットの矩形に「選択方法」を設け、「ドラッグ」を初期値、「2点クリック」を選択肢とする。

| 状態 | 操作 | 結果 |
| --- | --- | --- |
| 1点目を待つ | 左クリックして離す | その点を始点として記憶する。 |
| 2点目を待つ | ポインタまたは矢印キーで移動 | ボタンを押さずに仮枠を更新する。始点と対角点は全方向で正規化する。 |
| 2点目を待つ | もう一度左クリックして離す | 表示した枠を1回だけ撮影する。現行の最小矩形（2×2px）に満たない場合は終点を選び直せる。 |
| 2点目を待つ | Esc、または割り当て済みの右クリック取消 | 始点と仮枠を破棄して1点目の待機へ戻る。待機中のEscは撮影終了。 |

2点目の待機中は「ドラッグ中」の修飾キー割り当てを使う。入力プリセットの選択方法が「ドラッグ」なら、従来どおり左単押しで指定ウィンドウの枠内に見える画面を撮る。「2点クリック」では通常の左単押しを始点・終点に使い、Win短押しで切り替えたウィンドウ撮影は左単押しで確定できる。部品選択キーを保持した間は以下の操作を優先する。中クリックのデスクトップ撮影、固定サイズ、自由形にはそれぞれの操作を適用する。撮影終了やモード変更では未確定の点を破棄する。

### キーを押している間のコントロール選択（16）

「ショートカット」の「撮影範囲設定前の操作」と「撮影ドラッグ中の操作」に「押している間だけポインタ下の部品を選択」を追加する。両段階で個別に、既存の修飾キー1個または2個の組み合わせに割り当てられる。初期値は未割り当て。キーを押した間はボタン・入力欄を撮影候補として強調し、元アプリのキーボードフォーカスを保つ。たとえば「保存」の文字やアイコンにポインタを合わせると、保存ボタン全体に枠を出す。SSCaptureがクリックを受けてその枠を撮影し、元のボタンのクリック処理は呼ばない。

| 操作 | 表示と撮影 |
| --- | --- |
| 割り当てたキーを押す・押したまま移動する | ポインタ位置で識別できた部品を枠で強調し、ガイドがONならポインタ横に操作を表示する。暗転ONでは部品の内側を明るくし、OFFでは枠だけを重ねる。左右の修飾キーや自動リピートでも保持状態を正しく判定する。 |
| キーを保持して部品を左クリックする | 左ボタンを離した時点で表示中の部品の範囲を1回撮る。通常の矩形撮影では画面の見えている部分、WGC撮影では該当ウィンドウの画像内の同じ範囲を使う。 |
| 矩形ドラッグ中、または2点目の待機中に押す | 進行中の始点を保管して部品の枠を表示する。保持したままドラッグを離す、または2点目をクリックすると部品を撮る。確定前に割り当てを離したら同じ始点・現在のポインタから元の選択を続ける。 |
| キーを離す・組み合わせを外す | 部品の枠を直ちに消す。待機中に部品を左押下し、そのクリックの途中でキーを離した場合は撮影を取り消す。Windowsキーを含む組み合わせの解放が、重ねてWin単押しと解釈されることも防ぐ。 |
| 部品が見つからない・応答しない | 古い枠を消し「対象のコントロールが見つかりません」と案内する。画面全体や親ウィンドウを誤って撮影することを防ぎ、キーを離せば通常操作を続けられる。 |

このキーは静止画を選択している間に評価する。中ボタンで始めたモニター合成など、すでに対象を追加しているジェスチャーはそのまま完了させる。メニュー、Esc、フォーカス喪失、撮影終了では部品選択と保留中のクリックを解除する。選択状態の保存・インポート対象はキー割り当てとし、押下中の状態はセッション内で完結させる。[キー割り当て](../../../src/SSCapture/Capture/CaptureKeyMap.cs)・[キー設定画面](../../../src/SSCapture/UI/CaptureKeyEditor.cs)・[撮影セッション](../../../src/SSCapture/Capture/CaptureSession.cs)

取得の起点はSSCaptureの画面を除いて特定した撮影対象のHWND。既存のUI Automationワーカーに部品の位置を調べる要求を分けて設け、そのウィンドウ内のControl Viewを調べる。ポインタを含む可視要素から、撮影対象HWNDの内側で最も近い操作可能な部品まで親をたどる。ボタン内の文字やアイコンは所属するボタンを選ぶ。親に操作可能な部品を持たない独立した要素は、その要素自身の可視境界を候補とする。表示・確定には同じ物理pxの矩形を使う。UIAに部品がない場合は同じ親の可視の子HWNDも候補にする。画面を覆う撮影オーバーレイへの単純な点照会で、自分自身を対象にすることを防ぐ。[既存のUIAワーカー](../../../src/SSCapture/Services/CaptureContextWorker.cs)・[対象ウィンドウの特定](../../../src/SSCapture/Capture/CaptureNative.cs)・[MicrosoftのUIAツリー](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-treeoverview)・[HWNDからの要素取得](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationclient/nf-uiautomationclient-iuiautomation-elementfromhandle)

照会は1件ずつ非同期に行い、処理中に移動した場合は最新の1点だけを次へ渡す。キー解放・メニュー表示・対象変更後に届いた結果は破棄する。画面固定時は、取得元ウィンドウの位置や寸法が固定画像と食い違った候補を無効にする。表示に必要な矩形・種別を取得し、入力欄の値は読まない。「撮影情報」の記録がOFFでも利用できる。再撮影では元のウィンドウと部品を一意に識別できた場合に現在位置から撮り、識別できない場合は選び直しを案内する。部品撮影は表示した部品枠の画素を使う。第5節の四辺切り抜きは単一ウィンドウを選んだ操作に適用する。

## 5. 選択したウィンドウの内側を切り抜く（03）

「設定 → 出力プリセット → 出力・画像」に「選択したウィンドウの内側を切り抜く（px）」を置く。上・下・左・右を画像の物理pxで個別に指定する。0以上の整数を受け付け、初期値と旧設定で省略された辺は0px。全辺0pxなら全画素をそのまま渡す。

| 撮影操作 | 切り抜きの基準 |
| --- | --- |
| 囲うモードの左単押し、またはウィンドウ撮影の「見えている画面を撮影」 | クリックで特定したウィンドウの枠内に見える画面。重なっている別の窓やメニューの画素も含む。 |
| Win短押し後にプレビューしたウィンドウを左単押し（WGC） | 手前にある同じアプリの所有ダイアログも合成した、プレビューと同じ画像の外周。横にはみ出したダイアログもこの画像に含まれる。 |

撮影操作が「単一ウィンドウを選択」のときに適用する。任意矩形・2点クリック・固定範囲・部品単体・複数ウィンドウを手動でたどる合成・デスクトップ・録画はそれぞれの選択範囲を使う。再撮影やタイマーは、利用者が選んだ対象の識別情報と撮影方式を引き継ぎ、移動後の位置とその回の画像寸法で計算する。

**分担の実装手順**　単一窓の選択属性を `CaptureReplaySource.Windows` と `LastCaptureRecipe` に記録し、手動合成と区別する。出力処理で切り抜き後の座標を共用し、合成画像テストで画素、OCR、メタデータ、再撮影への属性伝搬を確認する。

1. 出力元画像の外周を画面物理座標 `(X, Y, W, H)` とする。WGCでは合成済みフレームの `Bounds` を使う。切り抜き後は `(X + 左, Y + 上, W − 左 − 右, H − 上 − 下)`。左右または上下の合計が元寸法以上なら該当軸を知らせて出力を止める。残り1pxは有効。
2. 切り抜き → 入力プリセットの外側の白余白 → 減色の順に1回だけ加工し、コピー・保存・外部編集・ピン留め・履歴・通知に共用する。たとえば `(100, 50) 640×480px` で上24、下8、左6、右10pxなら `(106, 74) 624×448px`。白余白10pxを付けると644×468pxになる。
3. OCRには切り抜いた範囲を渡す。通知にはその原点と幅・高さを表示する。ピン留めの配置、XMP/JSONの相対座標、再出力時の二重加工も、元の画像と加工結果の原点・寸法を使い分けて照合する。

**output分担の実装結果**　囲うモードの左単押しと「見えている画面を撮影」は、選択した窓の可視枠を使う。WGCは所有ダイアログを含む合成フレームの外周を使う。出力時に切り抜き後の物理座標をOCR・通知・履歴・ピン留め・撮影情報へ反映し、再撮影のレシピは切り抜き前の対象と条件を保持する。旧プリセットは四辺とも0pxで読み込む。

**親への引き継ぎ**　タイマーは選択結果の `ReplaySource` を `LastCaptureRecipe.Create` に渡し、窓の取得は `InstantCapture.TakeReplayWindowsAsync`、出力はその戻り値の `Source` を付けて `InstantCapture.DeliverAsync` または `OutputRouter.ScreenshotAsync` に渡す。任意矩形、部品選択と手動合成では `IsSingleWindowSelection` を付けない。選択中メニューの切り抜き一時切り替えは要求17のメニュー側で扱う。

## 6. 撮影操作を画面共有・配信に表示する（07）

基本設定の「選択範囲」に「撮影操作を画面共有・配信に表示する」を置く。新規・旧設定とも初期値はOFF。撮影中は右クリックでその回だけ切り替えられる。対象はDiscord・Zoomでモニター全体を共有する場合と、OBSの「画面キャプチャ」でモニターを収録・配信する場合。

| 表示先 | 配信OFF | 配信ON |
| --- | --- | --- |
| 利用者の画面 | 撮影中の各表示設定に従う | 同じ設定・同じ濃さで表示する |

## 8. 編集アプリと受け渡しファイル（04・13）

**編集アプリ**　設定の「外部アプリ」→静止画の「新規」にSnipping ToolとScreenpressoを追加する。端末に登録され、PNGを渡す起動経路を解決できるアプリを選べるようにする。既存のペイント・PPPaint・任意exeの登録方式を維持する。

- Snipping ToolはWindowsのPNGファイル関連付けから対象アプリを指定して起動する設計とする。OSの既定アプリ設定は変更しない。新しい切り取りを始める `ms-screenclip:` と、今回渡したPNGを編集画面に開く操作は別々に検証する。[Windowsのファイル指定起動](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-iapplicationactivationmanager-activateforfile)・[Snipping Toolの撮影プロトコル](https://learn.microsoft.com/en-us/windows/apps/develop/launch/launch-snipping-tool)
- Screenpressoは公式マニュアルにある「プログラムから開く」の登録を利用する。アプリ名や存在するexeだけで編集対応と判定せず、該当ハンドラーに既存PNGを渡す。どちらの製品も、固有の絵柄を持つテストPNGが編集可能な状態で開き、再撮影が始まらないことを実機で確かめる。[Screenpresso公式マニュアル「Edit other images」](https://www.screenpresso.com/docs/ScreenpressoHelp.pdf)
- [外部アプリの登録モデル](../../../src/SSCapture/Services/ExternalApplication.cs)に起動方式を持たせ、旧データは従来の「exe＋引数」として読む。組み込みのファイル関連付けは安定した識別子で保存して使用時に再解決する。通常出力、通知の編集ボタンとダブルクリック、出力再試行は同じ起動処理を使う。未導入・アンインストール時は対象名を表示し、成功した他の出力を保つ。[現行の関連付け検証](../../../tests/SSCapture.Tests/StoreEditorSmoke.cs)

**分担の実装手順**　PNGに関連付けられたハンドラーを使用時に検索し、通知と直接編集で同じアプリ解決を使う。遅延生成には撮影時の命名条件を使い、同名の並行生成と所有ファイルの回収を隔離試験で確認する。実アプリでのPNG編集は統合後に確認する。

**未保存時の命名**　撮影時刻、撮影種別、範囲名、出力プリセットの命名パターンをひと組で保持する。通知を遅れて開いても撮影時の値を使う。通常保存、外部アプリへの直接出力、未保存通知のドラッグと編集、再試行に同じ `FileNamePlan` を渡す。録画も完成MP4を外部へ渡す場合は同じ規則を使う。[命名・連番](../../../src/SSCapture/Services/FileNamePattern.cs)・[衝突時の保存](../../../src/SSCapture/Services/CaptureStorage.cs)

- 出力プリセットの「命名パターン」は未保存時も編集可能にする。「保存フォルダー」「保存後に開く」は保存やピン留めからの保存で実際に使う条件に合わせる。単なるクリップボードへのコピーはメモリで完了し、通知用ファイルはドラッグ・編集時に初めて生成する。外部アプリは完成ファイルが読める状態になってから起動する。
- `{ocr}` では撮影時に確定した文字列を再利用する。未保存で確定文字列がなく実ファイルが必要になったときは、保持した画像を対象にその場で認識する。取得不能時は現行CLIと同じ「OCRなし」を使う。キャッシュだけのために撮影中の入力ダイアログを増やさない。
- 同じ候補名で複数回・複数プロセスから生成しても上書きしない。共有の作業場所で既存の候補生成と排他的な公開処理を使う。`{##}` なら `01`、`02`、連番なしで衝突した場合は `_0001` 以降を付ける。削除対象は自プロセスが所有する生成物として識別し、現在の1分保持・次回起動時の回収を引き継ぐ。新しい名前を理由に作業場所のPNGを一括削除しない。保存済み画像とドロップ先へ移動した画像は所有対象から外す。
- テストでは同時生成と期限切れ回収を競合させ、利用中のファイル、同名であとから作られた別ファイル、別プロセスのファイルの保護を確認する。通知ドラッグがアプリへ渡すのは従来どおり画像1件とする。

**output分担の実装結果**　静止画の通知は、右クリックで利用可能な画像編集アプリを選べる。通常の編集ボタンは結果の種別と一致する登録を解決する。PNG関連付けは実行時に確認し、Windowsの関連付け既定は保持する。通常保存、直接編集、通知、再試行で撮影時の命名条件を使う。確定文字列がない静止画の `{ocr}` は、最初に実ファイルが必要になった時点で認識し、同じ撮影の受け渡しで再利用する。旧版で未検証だった無効な命名パターンには作業ファイルの既定名を使う。未保存の録画でOCR文字列を取得できないときは「OCRなし」を使う。

## 9. 定期・時限キャプチャ（10）

トレイの「タイマー撮影」で対象・出力・時刻を選ぶ。時限は指定秒数後またはローカルの指定日時に静止画を1枚、定期は指定間隔で指定枚数または停止まで撮る。次回予定と停止はトレイに表示する。

| 撮影方法 | 予約時の初期出力 | 実行時の動作 |
| --- | --- | --- |
| 定期 | ファイル保存のみ。保存後のフォルダー表示はOFF。 | 命名規則に `{ocr}` がある場合、各回の画像を自動認識し、現行CLIと同じく先頭の認識行を使う。取得できなければ「OCRなし」で続ける。命名規則に `{ocr}` がなければ命名のためのOCRは省く。 |
| 時限（1枚） | 予約画面で選んだ出力プリセット。初期表示は通常の既定出力。 | 指定時刻に予約した条件で1枚出力する。 |

- 定期の初期候補は予約専用に作る。初期プリセット「ファイル保存」をID `initial-output-file` で引き、その保存先・命名規則を使う。削除済みなら既定出力の保存先・命名規則から候補を作る。予約画面で保存先と規則を確認できる。通常撮影の既定出力（新規設定ではクリップボード）や保存済みプリセットを変更しない。
- 定期でも別の出力プリセットを明示して予約すれば、その出力先と保存後の動作を各回に適用する。初期候補での編集アプリ起動・フォルダー表示・OCR選択画面は0回。自動命名は保存先の既存ファイルと衝突しない名前を使う。[自動OCR命名の既存仕様](../../../docs/cli.md)
- 任意範囲は予約時に1回選ぶ。固定位置は登録範囲、選んだウィンドウは既存の対象識別情報と撮影方式、モニターは既存の識別子を保持する。開始時の入出力条件を控え、各回の実行時に新しい画素を撮る。予約後に前面のアプリが変わっても、選んだ対象に追従する。
- 待機はUIを占有しない。定期の初回は予約画面が消えた時点で撮り、以後は開始時点からの間隔を単調時計で測る。10秒間隔で3枚なら予定は0・10・20秒。指定日時はオフセット付き時刻へ変換する。過去の時刻・0以下の間隔や回数は設定時に知らせる。各回は同時に1件まで。ロック・スリープ・先行撮影中に過ぎた回を復帰直後にまとめて撮らない。定期は次の予定へ進み、指定枚数は成功枚数で数える。時限1回が実行できなかった場合は理由を通知して終了する。対象消失・出力不能は予約を止めて知らせる。
- 停止は次回の予約を取り消し、生成中のファイルは既存の原子的保存で処理する。アプリ終了で予約を解除する方式を初版の設計とする。アプリ終了後も必要な定期実行は現行のタスクスケジューラ用CLI例が利用できる。

### タイマー担当の実装・検証

## 10. 設定の持ち運び（11）

基本設定に「設定をエクスポート」「設定をインポート」を設ける。書き出しはUTF-8 JSON、形式名と形式バージョンを持つ。対象は基本設定、入出力プリセットとそのID、静止画のキーと入出力を組み合わせた一覧（既定参照・移行した即時出力条件を含む）、キー・マウスの割り当て、配信表示・拡大鏡の設定、外部アプリの登録、通知と履歴の設定。画像、履歴本体、直前の撮影結果、一時ファイル、OSの自動起動登録、実行中の予約は含めない。

1. 取込は新形式と旧版の `data/settings.json` を判別する。候補をメモリに読み、既存の設定移行・正規化・検証を使う。通常起動時の読み込みエラーから初期値を作る経路は、インポートの成功に使わない。不明な将来版、壊れたJSON、重複キー、参照切れは明示する。
2. アプリ内で置換対象の件数、外部アプリの実行先・引数、端末依存の保存先・モニター・マイクの解決状況を表示する。未解決の端末固有値は該当箇所を選び直せる。読込やプレビューで外部アプリやタイマーを起動しない。
3. 「適用」で全体を置換する。書き込み前に旧設定を回復できるよう確保し、キーの再構成とファイル更新を一単位にする。失敗や取消では現設定と稼働中のキーを保持する。開いている設定画面・トレイに新しい内容を反映する。履歴保持をOFFにするなど既存状態に影響する差分は適用前に表示する。

実装は[設定の読込・旧版移行](../../../src/SSCapture/Services/SettingsStore.cs)、[プリセットの移行](../../../src/SSCapture/Services/PresetSettings.cs)、[設定の適用とフック交換](../../../src/SSCapture/TrayApplicationContext.Settings.cs)を共用する。アプリ別の実行パスや保存先を含むため、書き出し先は利用者が選ぶ。

### 自動起動の適用ボタン（18）

「基本」の「自動起動」ラベルのすぐ横に「自動起動を適用」を置く。自動起動のチェックをOSの登録状態から変更したときだけ、ボタンを有効にして濃い緑の背景と白文字で表示する。チェックを元に戻したとき、適用中、適用後に登録状態と一致したときは通常の無効表示に戻す。緑を識別できない利用者にもボタン名・有効状態とキーボード操作で分かるようにする。

登録または解除はこのボタンで確定し、画面右下の「保存」は他の設定を保存する。新規の既定はOFF。登録時の `--startup` による無表示起動とKotorinToysと共有するOS予約を引き継ぐ。適用の成否は状態欄に示す。設定の取込でもOS予約を変更しない。[基本設定の行](../../../src/SSCapture/UI/SettingsForm.cs)・[適用ボタンと状態の読戻し](../../../src/SSCapture/UI/StartupSettingsControl.cs)・[自動起動の登録](../../../src/SSCapture/Services/StartupRegistration.cs)

