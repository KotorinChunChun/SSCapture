## 1. 開始条件と工程

- 設計段階の成果物は要求・設計・このタスク表のみ。ソース、個人設定、製品版番号、公開資産を変更しない。
- 実装はユーザーの開始指示後に行う。R08の履歴分離とR07の静止画ファイル対象・既定OFFは、要求書の「設計上の解釈」を再確認する。
- 設計値の通知32/48 DIP、50ms間隔、離脱1秒、UIA取得250msは仮値。実測結果と確定値を実装報告へ記録する。
- 工数欄は相対規模。小=局所変更、中=複数箇所の接続、大=プロセス・保存状態等の横断変更。時間見積もりではない。
- P1～P6を順に進める。各フェーズの自動テスト・Releaseコンパイル・差分検査を終え、問題なければコミットして次へ進む。実機確認が残る項目は別に未検証と記録し、製品の完了条件とは区別する。

## 4. 実装時の検証方法

次は実装後に実行するコマンド例。今回の資料作成では製品ビルドを行わない。

```powershell
Set-Location 'C:\develop\KotorinToys\tools\SSCapture'
pwsh -NoProfile -File .\scripts\test.ps1 -OutputPath 'dev/history/v0.2.0/logs/P1-run01/tests'
git diff --check
```

- 既存の`test.ps1 -OutputPath`はReleaseコンパイルと通常テストを行う。フェーズ/実行回ごとに出力先を変え、起動中のテスト用画面とのDLL競合を避ける。
- `scripts/build.ps1`は`artifacts/app`への発行も行うため、コンパイル確認だけの代用として実行しない。常駐版の置換やプロセス停止を暗黙に行わない。
- GUI受入は実装後の最終確認時に専用テスト画面で録画する。生ログ・PNG・JSON・動画・録画台帳は`dev/history/v0.2.0/logs/<実行識別子>/`へ置き、Gitへ登録しない。
- 自動テスト成功、模擬データ成功、DWM実画面成功、別PC/複数モニタ成功は別々に報告する。録画だけで画素比較の代用にはしない。
- UIA待機時間、通常/高負荷/初回起動の撮影遅延、OFF時の追加負荷、通知の保持操作を測定する。結果を見て仮値を確定し、時間上限超過や恒久停止がないことを確認する。
- 最終報告に各テストの実施条件・結果・未実施理由を残す。実装・テストの成功を公開完了や常駐版更新と混同しない。
