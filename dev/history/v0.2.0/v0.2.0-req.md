# v0.2.0 要求定義

状態: 設計段階。実装は未着手。現行製品版はv0.1.2のまま。v0.2.0は新機能追加を含む次版の候補。

## 要求原文（2026年10月20日）

- [ ] R01: 撮影時に設定画面を非表示にする機能があるようだが、フェードアウトが間に合っていない。
- [ ] R02: 通知画面にマウスポインタが近づいている間は消さない工夫が欲しい。開こうとしているかもしれないため。
- [ ] R03: 画面暗転OFF。
- [ ] R04: 出力先がファイルではないとき保存フォルダと命名パターンは無効。
- [ ] R05: 外部アプリは追加したい。
- [ ] R06: 「プリセット」名は「出力プリセット」にする。
- [ ] R07: UIA情報、マウスポインタ情報を記録する。撮影対象に対する相対座標、フォーカスしているUI、アプリケーション情報（exe、class、title）。
- [ ] R08: 撮影履歴は別。
- [ ] R09: 「範囲登録」は「入力プリセット」にする。
- [ ] R10: 固定範囲の再撮影ショートカットキーを割り当てたい。

## 確認回答

### Q01: 暗転OFFの意味

- 質問: 撮影中の暗転を初期設定でOFFにし、設定でONへ戻せる仕様か。撮影開始時の画面固定とは別設定とする。
- 回答: 「初期設定OFF・設定でONにできる」。

### Q02: 外部アプリの選択方式

- 質問: 複数登録から1つ選ぶか、複数アプリへ同時出力するか。
- 回答: 「複数登録して1つ選ぶ」。

### Q03: 情報の保存方式

- 当初の質問: 撮影時に1回取得し、画像と同名のJSONファイルへ記録する方式でよいか。
- 回答: 「画像ファイルのメタデータに書き込むことも考えてる。一般的にどうされることが多いか。」
- 比較後の質問: 「記録方式は『PNG内のXMPを基本にする』で設計を進めてよいですか？ UIA・座標・アプリ情報は独自項目として定義します。」
- 回答: 「PNG内のXMPと別JSONを両方選べる」。

## 設計上の解釈

以下は要求原文や確認回答とは区別した設計案。変更が必要ならこの欄と設計書を更新する。

- R08は、撮影履歴を入力・出力プリセットとは別画面にし、設定上も独立した区分にする。
- R10は、幅・高さだけを固定してカーソルへ追従するモードではなく、登録した位置・幅・高さを選択画面なしで再撮影する操作を指す。
- R07の初版対象は静止画のファイル保存。保存方式は「なし／PNG内XMP／別JSON／両方」。既定は「なし」。クリップボードだけの撮影、外部アプリだけへの一時ファイル、動画には新しい記録を自動追加しない。
- R07の「フォーカスしているUI」とポインタ下のUIは別項目として記録し、同じ要素であると仮定しない。連続したマウス軌跡の記録は含めない。
