## 1. ウィンドウ単押しのホイールと選択枠

**完了条件は、何を選んだかと、どこまでの画素を撮るかが、確定する前に同時に見えること。**

- [x] 通常の矩形モードで左ボタンを押し、ドラッグが成立する前にホイールを回すと、押下時に指したウィンドウ枠を基準に四辺を調整する。上1目盛りで各辺を1物理px広げ、下で縮める。左ボタンを離すと表示中の範囲を画面から取得する。押下前のホイールは従来どおりとする。
- [x] 押下後にドラッグへ移った場合はウィンドウ候補を解除し、矩形の始点・終点を使う。Esc、選び直し、次回撮影へ調整量を持ち越さない。WinによるWGC単一ウィンドウ撮影では元映像の上限を維持する。
- [x] 基準枠（対象ウィンドウまたはユーザーが囲った矩形）は実線で残す。調整後の撮影枠は破線とし、縮小時は内側、拡大時は外側に描く。両者が一致したら1本だけ描く。対象を動かした場合も基準枠を追従させる。出力プリセットの白い余白は画像生成後の処理とする。
- [x] 入力判定は [CaptureSession.Optics.cs](../../../src/SSCapture/Capture/CaptureSession.Optics.cs)、枠の保持は [SelectionGesture.cs](../../../src/SSCapture/Capture/SelectionGesture.cs)、描画は [CaptureOverlay.cs](../../../src/SSCapture/Capture/CaptureOverlay.cs) を起点に変更する。再描画領域には移動前後の両方の線を含める。

**関連箇所の提案**　固定サイズ・固定位置・2点クリック、単一コントロールでも、基準と撮影範囲が異なるときだけ同じ線の規則を使う。拡大鏡の赤線と暗転境界は撮影枠に合わせ、ポインタ横には調整時だけ対象寸法と撮影寸法を併記する。既存の暗転OFF、ガイドOFFを尊重する。

**検証**　ホイール入力が単押し経路で無視される失敗を先に再現する。各辺の外側に異なる色を置いた画像で、左単押し・矩形・2点クリックの枠と取得画素を突き合わせる。800×600に上2目盛りなら基準枠800×600、撮影枠804×604、下2目盛りで再び1本になる。縮小、Spaceでの基点変更、画面端、負座標、配信表示、別モニターでの残像も確認する。WGCの元映像外や出力時の白枠を画面から取得しないことを確認する。

## 2. 複数コントロールの背景付き矩形と描画領域撮影

- [x] Ctrlドラッグで選んだ全コントロールの外接矩形を物理ピクセルで求める。コントロール間の背景やラベルを含む矩形画像を取得する。プレビュー、保存、コピー、履歴、再撮影で範囲と背景の取得元を揃える。[コントロール選択](../../../src/SSCapture/Capture/CaptureSession.Controls.cs)・[ドラッグ処理](../../../src/SSCapture/Capture/CaptureControlDrag.cs)
- [x] ウィンドウ撮影で「ウィンドウ全体」「描画領域のみ」を選べるようにする。既定は全体。描画領域はWindowsのクライアント領域を画面上の物理座標に変換し、画面取得またはWGCフレームの座標へ対応付ける。再撮影時は現在位置と寸法を取り直す。

**背景の取得元**　WGCでは選択したウィンドウの描画を重なり順に合成し、選択したウィンドウの外はデスクトップ画像を使う。画面取得では外接矩形全体に表示されている画素を使う。

**検証**　色付きの親画面に離れた入力欄と中間ラベルを置き、矩形内部の背景画素まで比較する。遮蔽あり、別ウィンドウ、再撮影も対象とする。描画領域はクライアント寸法既知の窓を用い、ウィンドウ枠・タイトルバー・DPI差・別モニターへの移動を含めて出力寸法と端の画素を確かめる。

## 3. ウィンドウ指定CLIと再撮影キー

- [x] [撮影CLI](../../../src/SSCapture/Services/CaptureCommandLine.cs) に、ウィンドウハンドルによる一意指定と、プロセス名・タイトルによる探索を追加する。引数例の案は `--capture-window --hwnd 0x1234` と `--capture-window --process app.exe --title "資料A"`。描画領域のみの指定にも対応し、GUIと同じ取得処理・出力プリセット・終了結果を使う。該当なし、複数一致、取得直前の閉鎖は誤撮影せず理由を返す。候補一覧を返す独立コマンドは追加提案とする。
- [x] 「直前の設定で再撮影」の既定を **Win＋Ctrl＋Alt＋S** にする。新規設定と「初期設定に戻す」で反映し、既存ユーザーが設定したキーや明示的な「なし」を保つ。旧版で未割り当ての理由を識別できない場合は既存値を優先する。通知と設定表には実際の割り当てを表示する。

**検証**　同一プロセスにタイトルの異なる窓を2つ作り、ハンドル指定、タイトルでの絞り込み、曖昧一致、消滅、描画領域指定をCLIから確認する。新規・既存・初期化・キー競合を検査し、再撮影が直前の対象・入出力条件で新しい画像を取得することを確認する。

## 4. 通知と履歴からの受け渡し・履歴整理

- [x] 保存に成功した撮影の通知に「ファイルのパスをコピー」を追加し、絶対パスをテキストとして渡す。未保存・保存失敗では項目を表示しない。ファイルが事後に消えた場合に無効なパスを成功扱いしない。
- [x] [履歴画面](../../../src/SSCapture/UI/HistoryForm.cs) から通知と同じ操作で画像をドラッグできるようにする。[既存のドラッグ処理](../../../src/SSCapture/Services/NotificationFileDrag.cs) を共用し、保存済み画像をフォルダへ通常ドロップすると移動、Ctrlでコピー、アプリへは画像を渡す。未保存画像はドラッグ開始時に作業用PNGを生成する。キャンセルや繰り返し操作で画像を失わないようにする。
- [x] 履歴に選択項目の削除を追加し、複数選択に対応する。履歴の削除で保存済み画像を消さない。
- [x] 設定と履歴画面で保持期限・消去条件を確認可能にする。

**保持期限**　20枚・256 MiBまでを保持する。保持日数は0～365日で、0は日数による期限なし。明示的にONにすると、履歴用画像をディスクに保存して再起動後に復元する。

**検証**　移動後の履歴から再ドラッグ、コピー、アプリへの受け渡し、未保存画像、ドロップ取消を確認する。保持期限は注入した時計で境界時刻を検証し、期限と枚数・容量上限が同時に効く場合、選択中・ドラッグ中の期限到来も試す。個別削除・一括削除・期限切れのいずれでも元の保存ファイルが残ることを確認する。

## 5. OneOCRで文字・表をコピー

- [x] 通知・履歴の静止画に「文字をコピー」「表をコピー」を追加する。対象はその項目の撮影画像とし、保存OFFでも使えるようにする。画像コピーとOCR命名に影響させず、ユーザーが操作した時点でローカル認識する。
- [x] [既存のOneOCR連携](../../../src/SSCapture/Services/OneOcr.cs) は行文字列を取得している。文字コピーでは改行を保持し、命名用の空白除去や行数制限を適用しない。表は利用中のOneOCRから取得できる位置情報を先に検証し、行・列を復元してタブ区切り、行は改行で出力する。空セルで後続列を左に詰めない。
- [x] 表の判定が不確かな場合はその旨と文字コピーの選択肢を示す。認識失敗・取消・空結果では既存のクリップボードを保つ。

**検証**　既知の文字列、改行、数値、空セルを含む表を用意し、認識結果とクリップボード形式を個別に検証する。位置情報からの表復元テストと実エンジンによる認識結果を区別する。Excelへの貼り付けは列位置まで確認する。結合セル・折り返し・罫線なしの表は、実測した対応範囲を記録する。

### サインイン時に毎回の承認を省く構成

このPCのSSCaptureは利用者が書き換えられる導入先から動作する。現在のKotorinToysではSSCaptureを含む5ツールを共有予約から起動している。利用者が書き換えられるEXEを、タスクから最高権限で起動する構成では、EXEや依存DLLが差し替えられても次のサインインで昇格して実行される。SSCapture本体には実行ファイルを指定できる外部編集、OCR、動画処理の設定もあるため、本体EXEだけを保護しても十分ではない。

第一案は、管理者アプリを操作中の撮影キー受付だけを専用の小さな補助プロセスへ移す。補助と依存ファイルは一般権限で変更できない配置に発行し、登録済みの撮影コマンドの通知だけを通常権限のSSCaptureへ渡す。外部アプリ起動やユーザー設定の処理は通常権限側で行う。管理者アプリの前面で撮影や領域選択も通常権限のまま完了できるかを先に確認する。

SSCapture全体の昇格が必要な場合は、実行ファイルと依存ファイルを管理者のみ変更可能な場所へ配置し、書き換え可能な設定から任意のプログラムやDLLを管理者権限で読み込まない構成を先に設計する。登録・更新・削除は一度の昇格を伴う正式なインストーラーまたは設定処理を通し、現在ユーザーのSIDに限定した対話セッションのタスクを最高権限で起動する。KotorinToys本体は通常権限のままにする。[タスクのセキュリティコンテキスト](https://learn.microsoft.com/en-us/windows/win32/taskschd/security-contexts-for-running-tasks)

直接起動へ切り替えるときは、SSCaptureの専用タスクの作成・照合と共通設定の変更を既存の所有記録・復元手順で扱う。他ツールの起動方式と本体の共有予約を照合して保持し、旧経路と専用タスクから重複して起動しないことを検証する。実装に進む場合は、実サインイン、通常起動との競合、更新・削除、取消・失敗からの復元を検証する。

## KotorinToysからの起動と昇格の互換性

現行のSSCaptureは次の動作をする。起動の実装と現行の予約は変更しない。

| 起動の入口 | SSCaptureの動作 |
| --- | --- |
| 引数なし、または手動の `--settings` | 設定画面を開く。通常権限で単体の管理者設定がONならWindowsへ昇格を求める。承認を取り消した場合は通常権限で起動する。 |
| KotorinToysの「管理者として起動」 | 正式EXEを引数なしで起動する契約。管理者トークンを受け取ったSSCaptureは昇格を再要求せず、設定画面を開く。 |
| `--startup --launch-origin host_manual` | 実行元の権限で無表示起動し、管理応答に起動経路を返す。設定画面は準備完了後に `show` で表示する。 |
| `--startup --launch-origin via_kotorintoys` | 実行元の権限で無表示起動し、管理応答に起動経路を返す。 |
| 同じセッションに実行中の本体がいる | 既存プロセスを再利用する。設定表示は同じ権限の管理窓口かアプリ側操作を使う。管理者権限の本体に対する表示・終了を通常権限のKotorinToysから要求しない。 |
