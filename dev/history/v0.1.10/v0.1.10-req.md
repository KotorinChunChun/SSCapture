# SSCapture v0.1.10 候補の要求

- [x] 保存結果がない通知では「フォルダを開く」を表示せず、その位置のクリックを背後へ通す。
- [x] 未保存画像のサムネイルから従来どおりドラッグできる。
- [x] 通知の条件分岐と再表示をCLIで検証し、機能別試験をスクリプトから選べるようにする。

今回の範囲はローカル実装と検証。

- [x] 通知に部分失敗を明示し、再実行可能な失敗出力は通知から再実行できる。
- [x] ボタンの件数に合わせて配置と高さを調整し、編集ボタンの四隅を描画する。
- [x] サムネイルにドラッグの目印とホバー表示を加え、同じ寸法の繰り返しを省く。
- [x] 再撮影キーの案内を「直前の設定で再撮影するキー」に変更する。
- [x] 通常撮影ショートカットの直後に選択操作なしでEscを押した場合、前回の静止画出力結果を参考表示する。

- [x] 既存の撮影CLIで範囲と入出力プリセットを指定し、専用データからの単発撮影・保存先・結果を再現できるようにする。

## 撮影操作・通知の追加要求

- [x] 導入済みのPPPaintを静止画の外部アプリ候補に表示する。
- [x] 矩形ドラッグ中のSpaceで対角の起点へ切り替え、ポインタを元の始点へ移し、範囲を保持する。
- [x] ウィンドウを単押しで撮影した場合、通知にウィンドウ名を表示する。
- [x] 通知のサムネイルをダブルクリックして割り当て済みの編集アプリを起動する。
- [x] 撮影中のWin単押しでポインタ下の撮影対象を強調し、再度押すと解除する。
- [x] 修飾キーの単独・2キーの全10組とSpaceの動作を設定できるようにする。修飾キーの効果をポインタ近くに表示する。
- [x] 刻み幅の既定を1pxにする。

実キーと実アプリでの受け入れ確認は[実装報告](v0.1.10-imp.md#撮影操作通知の追加検証)を参照。
