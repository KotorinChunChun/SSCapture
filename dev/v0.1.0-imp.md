# v0.1.0 実装計画・点検報告

## 方針

- 既存の撮影・録画・OCR・独立出力・設定互換性を維持し、点検で根拠が得られた問題の修正と保守性の改善に絞る。依存バージョンや新機能は変更しない。
- 現在のバージョンをv0.1.0へ変更する。以後は通常の連番形式を使い、過去の日付型バージョンの要求・検証履歴は保存する。個人設定・画像・録画・OCRキャッシュを変更しない。
- 開発記録はdev配下に置く。現在の利用案内、構成・検証・更新手順、過去の版の記録を整理し、相互リンクで参照できるようにする。

## フェーズ

1. 現状確認と独立点検。Git状態・既存311件のテスト・ビルドを基準にし、版表記と運用規則を統一する。点検は撮影/録画、UI/サービス、文書/スクリプトを分担し、根拠・再現条件・影響を記録する。
2. 点検結果を評価し、必要な不具合修正と限定的なリファクタリングを実施する。変更ごとに既存の不変条件と意味のある回帰テストを確認する。
3. 利用・開発ドキュメントを整備し、ビルド・全テスト・差分検査を行う。現在の常駐版を安全確認後に更新し、バージョンと設定保持を確認する。

各フェーズの完了時に検証結果を記録してコミットする。実画面の撮影、マイク録音、個人クリップボード変更を通常テストへ混ぜない。ネイティブUI操作を追加する場合は対象と影響を事前に案内する。

### フェーズ2: 変更設計

- `DeliveryWait.CompletedWithinAsync(Task, TimeSpan, Task?)`へUI入力完了待ちと出力期限の判定を分離する。未完了入力には期限を使わず、入力後は既存10秒を適用。期限だけでは出力をキャンセルせず、既存の遅延完了観測を維持する。実処理の例外・キャンセルは呼び出し側へ返す。
- `AtomicFile.Write(string, Action<Stream>)`へ同一ディレクトリでの作成/置換を集約する。各Storeの検証・JSON形式・読込・旧設定移行は維持する。元ファイルとそのフォルダ外のデータを削除しない。
- `build.ps1`は従来の発行先を維持するが、依存/ライセンス不足と対象プロセス稼働時には発行前に拒否し、Releaseビルド・通常テスト後に発行する。復元済み環境の`-NoRestore`を用意する。配布パッケージ機能は追加しない。

### フェーズ2: 実施・検証結果

- `AtomicFile`へ同一フォルダ内の一時ファイル・置換処理を共通化した。書込み途中失敗、保存先ロック、一時ファイルの清掃失敗でも原本と元例外を保持し、別処理の一時ファイルを削除しないことを確認した。
- `DeliveryWait`へ入力待ちと配送期限の判定を分離した。入力終了前には期限を開始せず、入力後の期限だけが背景配送へ移行する。実処理のTimeoutExceptionやキャンセルは保持する。独立レビューでもUIスレッド復帰と画像寿命に問題なし。
- 明示された撮影時刻を既定PNGファイル名と履歴で共用するよう修正した。
- ビルドスクリプトは依存・ライセンス・対象プロセスを先に検査し、通常テスト成功後にも再検査してから発行する。設定・作業データの削除やプロセスの自動停止は追加していない。
- SDK照会はリポジトリ基点に固定した。独立レビューで見つかった「呼出元のglobal.jsonによる誤判定」と「一般CLIのDLL文字列をホストと誤認して拒否する」問題を修正した。
- Releaseビルド警告0・エラー0、**325件成功・0件失敗**（基準311件＋待機7件＋原子的保存/撮影日時7件）。ログ: `artifacts/review-v0.1.0/refactor-tests.log`。
- `test-build.ps1`は**7シナリオ成功・0失敗**。依存欠落、実行中、ホストDLL、メタデータ不明、途中起動、テスト失敗、復元有無の成功手順を注入した情報で検証した。実ビルド・常駐停止は行わないfixtureである。ログ: `artifacts/review-v0.1.0/build-fixtures.log`。
